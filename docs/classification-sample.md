# 貼文分類人工標註樣本（benchmark ground truth）

本檔是**人工判讀的標準答案**，用途有兩個：

1. 作為簡化 `output.schema.json` 的依據——只保留真的有人會讀、會拿來算價的欄位。
2. 作為後續 LLM 分類管線的 benchmark：上線前用同一批 post_id 回放，比對本表計算準確率。

## 資料來源

- 資料表：`fb_group_posts`（目前 108 篇，`publish_time` 範圍 2026-11-10 04:00 ~ 2026-11-12 07:16）
- 取樣：117 列／86 篇，刻意覆蓋單品出售、一篇多項、成套/半套、競標、收購、已售出、無價格、非配件品項、文字過短等情境
- `post_content`＝`text` 正規化空白後**前 100 字**（長文以 `…` 截斷），完整原文以 `post_id` 查回：`SELECT text FROM fb_group_posts WHERE post_id = '…'`。
- 判讀只使用 `post_content` 可見的資訊，不外接搜尋、不參考留言。

## 欄位定義

- `product_type`：`fb_taxonomy.category_key`，單列只給一個值。完整清單是 19 類（見 DDL 的種子資料）；本表用到其中 16 類（`gpu`/`ram`/`ssd`/`cpu`/`desktop`/`motherboard`/`laptop`/`psu`/`monitor`/`hdd`/`cooler`/`mini_pc`/`other`/`unknown`/`case`/`cable`），尚未出現的是 `console`/`network`/`peripheral`。
- `產品型號`：品牌＋系列＋型號＋規格（容量/時脈/尺寸），用原文語言；原文未標的欄位寫 `（○○未標）`；成套／半套以 ` + ` 串接內容並在括號註明「一組／半套／合標」。
- `價格`：單位一律 TWD 整數。`起標 N`＝競標起標價；`預算 A`／`預算 A-B`＝收購預算；`A*B`＝原文以單價×數量表示；`-`＝貼文未給價。原文寫「13.2萬」「7w」者已換算為 132000、70000。
- `purchasable`：`Y`＝這篇文現在能買到該品項（出售／競標進行中）；`N`＝買不到（收購或徵求、已售出、內容已被划掉）；`?`＝資訊不足，無法判定買賣意向。
- 判定規則編號（R1–R14）與逐案取捨見 docs/classification-decision-log.md。
